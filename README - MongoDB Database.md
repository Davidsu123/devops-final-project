Database: MongoDB
1. OverviewMongoDB serves as the database layer for this project. It provides a flexible NoSQL solution for storing and retrieving application data, such as the page visit counter.The deployment is based on Infrastructure as Code principles, with the entire configuration managed as version-controlled files within the Git repository.
2. Kubernetes Deployment ArchitectureThe database is deployed within the Kubernetes cluster and managed by Helm.StatefulSet/Deployment: MongoDB runs as a StatefulSet (or Deployment, depending on the chart configuration), which ensures a stable network identity and orderly management for stateful components.Persistent Storage: The data itself is stored outside the Pod on a Persistent Volume (PV). By using a Persistent Volume Claim (PVC), we ensure that even if the database Pod crashes or is restarted, the data will be preserved and will not be lost.Service: A Kubernetes Service exposes the database within the cluster, allowing our application to connect to it using a stable, internal DNS name.
3. Installation and ConfigurationInstallation via Helm: The deployment is handled by the official Bitnami Helm chart, which is known for its stability and robustness.Centralized Configuration File: All installation settings are centralized in the mongodb-values.yaml file. This file defines two critical parameters:auth: Sets the root username and password for the database.persistence: Enables the persistent storage mechanism and defines the disk size.
4. Security and ConnectivityTo avoid exposing passwords in plain text, the connection between the application and the database is secured as follows:Kubernetes Secret: The database password is stored within a secure Kubernetes object called mongodb-secret.Password Injection: The application's Deployment is configured to "inject" the password from this Secret directly into an environment variable (MONGO_PASSWORD) inside the application's Pod.Consistency: It is critical that the password defined in the mongodb-values.yaml file (for the MongoDB installation) is identical to the password stored in the mongodb-secret (for the application).
